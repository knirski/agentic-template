# Product Requirements Document

This document is the source of truth for product scope, behavior, and acceptance criteria. Replace
the guidance below when creating a project from this template.

## Problem

Describe the user problem, affected users, and current workaround.

## Goals

- State measurable outcomes the project must achieve.

## Non-goals

- State adjacent capabilities intentionally excluded from the current scope.

## Users and workflows

Describe each primary user and their end-to-end workflow.

## Requirements

Give every requirement a stable identifier and testable wording.

- **REQ-001:** Describe required behavior and observable acceptance criteria.

## Quality attributes

Define applicable reliability, security, privacy, accessibility, compatibility, and performance
constraints with measurable thresholds.

## Release criteria

List the evidence required before the product or milestone is considered releasable.

## Open questions

Record unresolved product decisions. Do not treat an open question as an implementation requirement.
